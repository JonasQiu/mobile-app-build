# 开发、验证与部署手册

## 1. 环境要求

- Node.js `>=22.13.0`
- npm
- 访问依赖 registry 的网络
- 若修改数据库 schema，需要 Drizzle migration 工具（已包含在项目依赖中）

Web 应用位于 `apps/web`。当前使用 vinext 构建 Cloudflare Workers 兼容产物，D1 作为 MVP 元数据数据库。

## 2. 本地启动

```bash
cd apps/web
npm ci
npm run dev
```

默认访问 `http://localhost:3000`。本地环境由 `vite.config.ts` 模拟 `.openai/hosting.json` 中声明的 D1 binding。

登录使用项目已约定的 MVP 测试账号。不要把测试密码写入 README、提交记录、Issue、日志或截图。

## 3. 常用命令

```bash
npm run lint          # ESLint
npm run build         # 生产构建
npm test              # 构建并执行渲染测试
npm run db:generate   # schema 变化后生成 migration
```

提交前最低要求：`npm run lint` 与 `npm run build` 成功。认证、项目 API 或数据库变更还必须执行对应接口回归。

## 4. 数据库变更

1. 修改 `db/schema.ts`。
2. 运行 `npm run db:generate`。
3. 检查 `drizzle/` 新 migration，不接受未说明的数据丢失操作。
4. 本地启动应用，验证旧数据库可以迁移或兼容读取。
5. 先发布兼容新旧代码的 migration，再进行字段切读或删除。

`app/lib/server-auth.ts` 中的 `ensureDatabase()` 目前用于 MVP 自举。进入多人或公开测试前，应把 schema 生命周期完全交给 migration，不在请求链路动态执行 DDL。

## 5. 当前部署形态

Mobile Build 产品站当前私有部署在 OpenAI Sites：

- 站点元数据：`apps/web/.openai/hosting.json`
- 数据库 binding：`DB`
- 构建产物：`apps/web/dist`
- migration：打包时放入 Sites 所需的 `.openai/drizzle` 目录

当前线上地址：<https://mobile-app-build-mvp.long229260097.chatgpt.site>

产品站的托管方式和“系统为用户生成的网站如何部署”是两个不同问题。后者必须通过 `DeploymentProvider`，当前决策是首个默认实现为 Vercel Preview，未来可增加 Sites、Cloudflare 或用户自有环境。

## 6. 发布流程

1. 完成代码检查、构建和必要的接口回归。
2. 确认 D1 migration 已生成并提交。
3. 将经过验证的源码版本保存到站点源码仓库。
4. 使用同一源码版本打包 `dist`、hosting metadata 和 migration。
5. 保存站点版本并优先私有发布。
6. 等待部署成功，使用返回的精确 URL 做首页和关键 API 检查。

不得在仓库 remote、配置文件或文档中保存短期源码写入凭证。

## 7. 上线后快速检查

- 未登录访问 Session API 返回 `401`。
- 正确登录后能查询项目列表。
- 创建项目后刷新页面，项目记录仍存在。
- 非项目所有者不能查询或更新该项目。
- 首页、分享图片和 `/preview` 正常访问。
- 服务端日志不包含密码、Session token、Cookie 或第三方 Secret。

公开测试前还需执行 [安全与运维方案](安全与运维方案.md) 的上线检查清单；当前固定账号只适合受控 MVP 验证。

## 8. 回滚与故障处理

- UI 或 API 回归：重新部署最近一个通过验证的站点版本。
- migration 失败：停止新版本发布，保留旧代码兼容路径；禁止直接删除线上表或字段。
- Session 大面积异常：撤销相关 Session，检查 Cookie、时钟和数据库状态后再恢复。
- 项目数据异常：优先从数据库备份恢复到隔离环境验证，不直接在线修补未知范围数据。
- Provider 故障：控制面应返回可重试失败，不把项目标记为 ready。

每次生产故障记录时间线、影响、根因、恢复动作和防复发项；敏感值全部脱敏。
