# 数据模型

## 1. 当前 D1 模型

当前请求链路通过 `ensureDatabase()` 幂等创建四张表。

### users

| 字段 | 说明 |
|---|---|
| `id` | 用户主键；ChatGPT 用户使用站点内稳定身份的 SHA-256 前缀生成，原站点所有者继续映射到旧主键以保留历史 |
| `username` / `username_normalized` | ChatGPT 显示名与归一化邮箱；邮箱只用于显示、唯一性和原所有者历史映射 |
| `password_hash` / `password_salt` / `password_iterations` | 旧本地登录的兼容字段；ChatGPT 用户不使用密码校验 |
| `status` | 账户状态 |
| `created_at` | 创建时间 |

### sessions（兼容保留）

| 字段 | 说明 |
|---|---|
| `id` | 旧本地 Session 主键 |
| `token_hash` | 旧 Session token 哈希 |
| `user_id` | 所属用户 |
| `expires_at` / `last_seen_at` / `revoked_at` | 旧会话生命周期；当前请求鉴权不再读取该表 |

### projects

| 字段 | 说明 |
|---|---|
| `id` | `prj_` 前缀项目 ID，也是 Runner 幂等键 |
| `owner_user_id` | 项目所有者 |
| `name` | 需求摘要名称 |
| `prompt` | 完整原始需求 |
| `status` | `queued`、`dispatching`、`building`、`ready`、`paused`、`delivered` 或 `failed` |
| `current_stage` | requirement/mobile-spec/implementation/build/deployment/paused/delivered/failed |
| `preview_url` | 通过 evidence 验证的外部 HTTPS URL；历史字段名暂未迁移 |
| `created_at` / `updated_at` | 时间戳 |

当前认证由 Sites 托管的 Sign in with ChatGPT 完成。服务端只信任调度层注入的稳定用户 ID、邮箱和可选显示名；缺少身份头的 API 请求返回 401。索引：users 归一化邮箱唯一、兼容 Session token hash 唯一、项目按 `(owner_user_id, updated_at DESC)` 查询。

### runner_endpoints

| 字段 | 说明 |
|---|---|
| `id` | 当前固定为 `primary`，为后续多 Runner 注册预留 |
| `endpoint` | Runner 最新登记的 HTTPS `/jobs` 地址 |
| `instance_id` | Runner 进程实例编号，用于识别重启 |
| `last_seen_at` | 最近一次通过服务端身份与健康检查的登记时间 |
| `rotate_requested_at` | 为后续远程 Runner 控制保留；当前本机修复流程不依赖该字段 |
| `updated_at` | 记录更新时间 |

该表只保存 Runner 连接元数据，不保存 Bearer token、模型凭证或任务输入。Runner 新建公网入口后调用受 callback token 保护的登记接口；控制面必须从公网复核地址返回的实例编号和部署能力，验证通过后才能覆盖该表。

## 2. 当前临时 Runner Job

Runner 内存 Map 使用 `projectId` 为 key：

```ts
type RunnerJob = {
  id: string;
  status: "queued" | "running" | "checkpointed" | "paused" | "delivered" | "failed";
  stage: string;
  progress: number;
  message: string;
  mode: "continue" | "rerun" | "step";
  targetStage?: "mobile-spec" | "implementation" | "build" | "deployment";
  checkpoints: string[];
  events: Array<{
    id: string;
    at: string;
    message: string;
    stage: string;
    kind: "progress" | "warning";
    progress: number;
  }>;
  updatedAt: string;
  error?: string;
  url?: string;
  evidence?: {
    mobileSpecPassed: boolean;
    buildPassed: boolean;
    deployPassed: boolean;
  };
};
```

事件最多保留 24 条，API 返回给项目列表时最多保留最近 12 条，UI 显示最近 6 条。Job 模型不持久，不能做审计或恢复执行中进程。

Runner 工作区当前持久化四类需求哈希状态：Mobile Spec 正式 marker 记录 change/pageSpecId，Mobile Spec progress marker 记录 propose/design/task 成功前缀与最近错误，输出 marker 记录 implementation/build/deployment，repair marker 记录实现或构建的最近诊断和累计尝试次数。对应产物包括五份 Markdown 规格文档、带 `generatedFiles` 文件账本的生成 manifest、构建日志和部署证据。只有哈希一致且必需文件存在的步骤才可复用；用户明确“重跑”时才整体清除。

## 3. 下一阶段持久模型

建议新增：

- `build_jobs`：目标项目、状态、stage、progress、message、幂等键、Runner lease。
- `job_attempts`：一次模型/构建尝试、开始结束时间、错误分类和预算。
- `job_events`：单调 sequence、type、payload、occurred_at，用于断线重放。
- `mobile_spec_artifacts`：change、artifact type、content hash、gate result。
- `checkpoints`：不可变源码快照、父 checkpoint、manifest hash。
- `build_artifacts`：日志、ZIP、构建输出的对象存储引用。
- `deployments`：Provider、external ID、URL、健康状态和生命周期。
- `approvals`：未来高风险动作审批。

## 4. 不变量

- 浏览器永远不能直接写 `delivered`、evidence 或 URL。
- 同一 attempt 的事件 sequence 不重复且不可覆盖。
- checkpoint 不可变；重试产生新 attempt，不覆盖成功基线。
- deployment 与 checkpoint 多对一，生产发布必须独立审批。
- Secret 不进入业务表、事件 payload、日志或文档。
- ChatGPT 身份只用于登录和用户级数据隔离；模型、Runner、构建及部署凭证始终来自平台配置，不读取访问者的 ChatGPT 对话、文件、Token 或账单信息。
- 当前只允许删除非进行中项目；生产化后还需可恢复期，并异步清理 artifacts 和派生部署。
- 全站共享 Runner 的 `dispatching/building` 项目最多 2 个；jobs 条件 UPDATE 是全局并发门禁，UI 计数不是授权依据。
- 浏览器不能直接写 endpoint；新地址必须由本机 Runner 返回，且控制面从公网验证 Runner 实例编号、健康状态和部署能力后才能登记。
- `ready`、`paused` 不计入并发上限；继续、重跑或单步执行产生新的 Runner job id，旧 job 的迟到事件不得覆盖新 job。

## 5. 迁移注意

`preview_url` 已承载真实交付 URL，仅因兼容保留名称；未来可无损迁移为 `delivery_url`。在多人或公开环境前，应将请求时 DDL 自举替换为正式 migration，并为 job/event 高频查询建立与实际谓词匹配的索引。
