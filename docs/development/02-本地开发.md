# 本地开发

## 1. 环境要求

- Web 使用 Node.js `>=22.13.0`；
- Runner 和 Mobile Spec 要求 Node.js `>=18`，建议统一使用 Web 所需版本；
- npm 可访问依赖 registry；
- Runner 机器具备文件系统、子进程和外网能力；
- Agent Provider 至少配置 Codex CLI 或 OpenAI API 之一；
- 需要对外验收时安装 `cloudflared` 和 `curl`，或配置其他 Deployment Provider。

## 2. 安装依赖

仓库没有根级统一安装命令，按包安装：

```bash
cd apps/web
npm ci

cd ../../packages/codegen
npm ci

cd ../mobile-spec
npm ci
```

不要替换现有 lockfile，也不要混用包管理器。

## 3. 启动 Web 控制面

```bash
cd apps/web
npm run dev
```

`.openai/hosting.json` 声明 Sites 项目和逻辑 D1 binding `DB`。本地数据库由 Cloudflare Vite 插件和 Miniflare 提供，端口以终端实际输出为准。

Web 常用环境变量：

| 变量 | 是否必需 | 用途 |
|---|---|---|
| `CODEX_RUNNER_URL` | 冷启动回退 | Runner 的 HTTPS `/jobs` 地址；D1 已验证地址优先 |
| `CODEX_RUNNER_TOKEN` | 是 | 控制面调用 Runner 的 Bearer Token |
| `RUNNER_CALLBACK_TOKEN` | 是 | Runner 回调和自动登记鉴权 |
| `SITE_OWNER_EMAIL` | 兼容场景 | 将原站点所有者映射到旧用户主键 |

## 4. 启动 Runner

开发环境建议使用只存在于本机的受限环境文件，再启动进程。不要把真实值写入仓库。

```bash
cd packages/codegen
npm run start:runner
```

Runner 最小配置：

| 变量 | 是否必需 | 用途 |
|---|---|---|
| `CODEX_RUNNER_TOKEN` | 是 | Runner `/jobs` 鉴权，必须与控制面一致 |
| `RUNNER_CALLBACK_TOKEN` | 是 | 回调和 Endpoint 登记鉴权 |
| `CODEX_BIN` | 二选一 | Codex CLI 路径 |
| `OPENAI_API_KEY` | 二选一 | OpenAI API Provider |
| `CODEGEN_RUNNER_PORT` | 否 | Runner 端口，默认 `5174` |
| `CODEX_WORKDIR` | 否 | Codex 只读工作目录 |

需要完整公网链路时再配置：

| 变量 | 用途 |
|---|---|
| `CODEGEN_CONTROL_PLANE_URL` | 控制站 URL，也是本机恢复接口允许的 Origin |
| `CODEGEN_AUTO_PUBLIC_TUNNEL=1` | 自动维护 Runner 控制 Tunnel |
| `CODEGEN_DEPLOYMENT_PROVIDER=cloudflare-quick-tunnel` | 启用当前验收部署 Provider |
| `CODEGEN_TUNNEL_BIN` | `cloudflared` 可执行文件绝对路径 |
| `SITES_BYPASS_TOKEN` | Runner 调用受限控制站登记接口时使用；不得提交 |
| `CODEGEN_DISABLE_CALLBACK=1` | 禁用主动交付回调，改由控制面拉取收敛状态 |

完整变量、默认值和超时配置见 [`packages/codegen/README.md`](../../packages/codegen/README.md)。

## 5. 验证服务连接

Runner 启动后先检查本地健康接口：

```bash
curl http://127.0.0.1:5174/health
```

健康响应至少满足：

```json
{
  "ok": true,
  "deploymentProviderConfigured": true
}
```

`ok` 为 false 时先检查 Token 和 Agent Provider；`deploymentProviderConfigured` 为 false 时检查 Deployment Provider。控制面会在占用并发名额前执行相同门禁。

## 6. macOS 常驻 Runner

验收机可以把 Runner 安装为当前用户的 LaunchAgent：

```bash
packages/codegen/scripts/install-runner-service.sh /tmp/mobile-build-runner.env
```

安装脚本会复制受限环境文件和 `cloudflared`、记录稳定 Node/npm 路径，并创建 `com.siteforge.runner` 服务。它适合开发验收，不等同于生产 Cloud Runner。

## 7. 本地开发注意事项

- Web 与 Runner 是两个进程，缺一不可；
- 浏览器不应直连公网 Runner API，产物读取必须经过控制面；
- 本地页面可用于交互开发，但 localhost 不能写入最终交付 URL；
- 不要在文档、终端截图或 Git diff 中保留真实 Token；
- 修改 D1 Schema 时同时更新 Drizzle Schema、migration 和运行时兼容建表逻辑；
- 修改 Runner 请求或状态结构时同时更新 Web 契约测试和协议文档。
