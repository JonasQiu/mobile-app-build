# 测试与排障

## 1. 提交前验证

Web：

```bash
cd apps/web
npm run build
npm run lint
node --test tests/*.test.mjs
```

Runner：

```bash
cd packages/codegen
npm test
```

Mobile Spec：

```bash
cd packages/mobile-spec
npm test
```

文档与 diff：

```bash
node scripts/check-docs.mjs
git diff --check
```

`apps/web` 的 `npm test` 已包含一次生产构建；需要分别看结果时使用上面的拆分命令。

## 2. 最小端到端验证

1. Runner `/health` 返回 `ok: true` 且部署能力已配置；
2. 提交一个仓库中从未预设的完整需求；
3. Mobile Spec 后出现 3 份预览并停在 `awaiting_approval`；
4. “换一组”只生成新预览，不出现 Codex 或 build 事件；
5. 确认方案后才进入 implementation；
6. 页面每 15 秒同步 Runner message 和 events；
7. delivered 包含三项 evidence 和外部 HTTPS URL；
8. 再次“继续”复用成功步骤，“重跑”才清空并重新确认预览；
9. 阶段卡片可以读取 Markdown、SVG、Manifest、构建日志和部署证据；
10. 第三个并发任务被服务端 409 拒绝，前两个结束或等待确认后释放名额。

## 3. 按阶段定位失败

| 现象 | 优先检查 | 处理原则 |
|---|---|---|
| D1 binding 不可用 | `.openai/hosting.json`、Vite Cloudflare 配置、部署资源绑定 | 修复环境或绑定，不修改业务状态绕过 |
| Runner 当前不可用 | 本地 `/health`、LaunchAgent、Runner Endpoint、控制 Tunnel | 恢复 Runner 或轮换 Endpoint，再按原模式派发 |
| Mobile Spec Gate 失败 | 规格 Markdown、progress marker、最近 Gate 错误 | 只续修当前失败子阶段 |
| 预览确认失败 | 当前 preview set、selected ID、D1 approval | 重新读取当前方案，禁止使用旧 ID |
| Manifest 重复路由 | `navRoutes`、生成文件账本、旧路由文件 | 让 implementation 定向修复并清理不再生成的文件 |
| `spawn npm ENOENT` | LaunchAgent PATH、Node 同目录 npm、`CODEGEN_NPM_BIN` | 这是执行环境故障，不调用 Codex 修改页面 |
| `npm ci` 或构建失败 | lockfile、真实构建日志、repair marker | 把真实诊断交给 Codex，复用规格和已确认预览 |
| 部署健康检查失败 | Tunnel 注册、DNS、HTTP 状态、Provider 配置 | 只重试或轮换部署地址，不重跑规格、实现和构建 |
| Runner 已成功但页面仍失败 | `GET /api/projects` 主动同步、回调鉴权、D1 终态 | 以可信 Runner 状态收敛，不让浏览器直接改状态 |

## 4. Runner 健康检查

```bash
curl http://127.0.0.1:5174/health
```

判断顺序：

1. 端口不可达：确认 Runner 进程或 LaunchAgent；
2. `ok: false`：确认 Token、Codex CLI/OpenAI Provider；
3. `deploymentProviderConfigured: false`：确认部署 Provider 与 `cloudflared`；
4. 本地健康但控制站不可达：检查 Runner Endpoint、Quick Tunnel 和 D1 登记；
5. Endpoint 已变化：等待自动登记，或使用页面“修复连接”人工轮换。

## 5. 调试原则

- 从失败阶段开始，不先全量重跑；
- 区分页面代码错误、工具链错误和公网连接错误；
- 先看 Runner 原始 message、事件和阶段产物，再看 UI 映射；
- 不通过手工写 D1 delivered 来“修好”状态；
- 不把 localhost 或未通过健康检查的 URL 当成交付成功；
- 调试输出必须裁剪系统路径、模型输入和 Secret；
- 修复后增加覆盖该故障的契约或单元测试。

## 6. 文档自动检查

`node scripts/check-docs.mjs` 会检查：

- 相对链接是否存在；
- 常见 Secret、Bearer Token 和私钥模式；
- 已知过时产品描述；
- Markdown/MDX 文档范围内的基础一致性。

`node scripts/sync-docs.mjs` 从源码生成 [实现状态快照](../实现状态快照.md)。不要手工编辑该快照。

## 7. 独立浏览器验收执行面

当平台浏览器后端不可用时，使用仓库内的回环 Chrome/CDP 执行面，不要复用开发者浏览器 profile 或
登录数据：

```bash
python3 scripts/acceptance-browser/surface.py start --local-production
node scripts/acceptance-browser/cdp-probe.mjs
python3 scripts/acceptance-browser/surface.py stop
```

完整能力、真实登录人工门禁、触屏/读屏边界与清理要求见
[独立验收浏览器执行面记录](../独立验收浏览器执行面记录.md)。执行面可用不等于产品 P0 通过，
独立验收专家仍需重做业务场景并保留自己的证据。
