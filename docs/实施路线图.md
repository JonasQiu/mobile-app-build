# 实施路线图

## 1. 当前基线

已完成：移动端需求入口、MVP 账号登录、D1 项目摘要、Mobile Spec 文本/链接来源解析。

已移除：关键词方案卡、前端计时构建、示例文件/日志、内置 Preview、本机 Desktop Agent 执行入口及其协议代码包。

未完成的关键闭环：控制面任务状态机、网站到执行器的真实事件流、Cloud Runner、动态源码 checkpoint 和真实部署 Provider。

## 2. 实施策略

采用两条并行但有门禁的主线：

- **产品闭环线**：先以 Cloud Runner 打通新建 Next.js 项目的真实交付，快速验证用户价值。
- **Mobile Spec 完整替换线**：以旧 DSpec 行为为基线逐项去内网、补默认实现和端到端测试；任何条目未通过时不得宣布完整替换。

产品闭环可以先只启用 Web schema，但 `mobile-spec` 包的稳定版发布必须等待 H5、iOS、Android、Harmony 全矩阵通过。

## 3. 里程碑

### M0：文档与边界基线（已完成）

- 产品范围、总体架构、API、事件、数据、安全和路线图形成统一文档。
- 当前演示能力与目标能力明确分层。
- 完成标准：文档索引可从根 README 访问，术语和状态无冲突。

### M1：协议和任务控制面

- 实现 TypeScript schema 和运行时校验（协议契约见 [API 与事件协议](API与事件协议.md)，当前无独立代码包）。
- 新增 messages、plans、jobs、attempts、events、approvals 数据表。
- 实现任务状态机、幂等、租约、取消和 SSE 断线恢复。
- 把 UI 的计时器阶段替换为服务端持久化事件。

验收：可运行一个不写代码的 mock executor，但所有进度都来自真实协议和事件库；刷新、断网和重复提交不会重复任务或丢状态。

### M2：Mobile Spec Web 核心通用化

- 完成 RequirementSource、Proposal、Specs、Design、Review、Tasks、Coding、Verify、Archive。
- 清除 Web 工作流中的滴滴内网、私有包、私有知识和专属字段依赖。
- 每个能力同时具备完整文本 Skill、机器协议和行为测试。
- 建立内网残留扫描与 fixture 端到端 gate。

验收：在无滴滴网络和账号的干净环境中，仅用公开工具完成固定 Web 项目全生命周期；失败恢复、stale 和 archive 行为与基线等价。

### M3：Cloud Runner 真实 Next.js 闭环

- 建立隔离 Runner、工作区、结构化动作和网络策略。
- 实现 AgentProvider，首个实现连接 OpenAI Responses API。
- 实现 Artifact Store、源码 checkpoint、ZIP 下载和日志脱敏。
- 实现一个 Preview DeploymentProvider。
- 用三条固定需求完成真实生成、验证、构建、部署和健康检查。

验收：手机输入一句话后可获得动态生成的外部 HTTPS URL；刷新浏览器、Runner 重启和部署瞬时失败都能恢复或明确终止。

### M4：Desktop Agent（已移除，暂未纳入当前范围）

原计划的本机执行器里程碑，涵盖同账户登录、二维码配对、设备令牌、出站 WebSocket、能力上报、心跳、租约、工作区绑定、本机策略与凭证代理。该组件已从仓库移除，真实执行统一走 Cloud Runner；下列内容留作未来重新引入时的设计参考：

- 同账户登录、二维码配对、设备令牌和撤销。
- 出站 WebSocket、能力上报、心跳、租约和升级策略。
- 目录选择、工作区绑定、本机策略、凭证代理和进程树管理。
- 实现本机项目创建、继续修改、暂停、取消和 checkpoint。

验收（未来重新引入时）：电脑在线时手机可驱动授权目录构建；Agent 不能访问未授权目录，设备撤销后立即停止接收新任务。

### M5：Mobile Spec 全平台完整替换

- 完成 iOS、Android、Harmony 的公开工具链适配和全阶段 fixtures。
- 完成 App Bridge、调试、预览、字体/CDN、Analytics、上下文同步和 obs 的公共默认实现或中立 Adapter。
- 完成旧状态迁移、升级/降级、跨 Agent 兼容和发布文档。
- Mobile Spec 完整替换矩阵全部变为“已完成”，并附测试证据。

验收：无内网环境端到端测试全部通过，残留扫描为零，才允许发布 `@mobile-app-build/mobile-spec` 稳定版本并声明完整替换。

### M6：公开测试与运营能力

- 邀请制账户、多项目配额、成本预算、限速和滥用检测。
- Session/设备/授权管理、数据导出和项目删除。
- Provider 指标、告警、备份恢复和故障演练。
- 隐私政策、服务条款、许可证清单和数据保留策略。

## 4. 近期开发顺序

建议接下来的 4 个工程迭代按以下顺序：

1. 任务状态机类型与数据库 migration。
2. 服务端任务状态机、mock executor 和 SSE，替换前端定时器。
3. Mobile Spec Web 核心去内网与端到端 fixture。
4. Cloud Runner + AgentProvider + Preview DeploymentProvider。

这样可以先稳定所有执行器共用的契约，再接入具有成本和安全风险的真实 Agent。

## 5. 发布门禁

### “真实 Web MVP”完成定义

- 三个固定场景端到端成功率达到团队设定阈值。
- 无演示 FILES、LOGS、定时器阶段或固定 `/preview` 交付。
- 支持取消、重试、断线恢复、ZIP 下载和完整交付摘要。
- 安全与运维文档中的“公开测试前必须补齐”全部完成。

### “Mobile Spec 完整替换”完成定义

- 迁移矩阵所有条目均有新实现、默认公开能力和自动验证证据。
- H5、iOS、Android、Harmony 全生命周期在干净环境通过。
- 内网域名、私有包、专属平台字段和隐含知识扫描为零。
- 名称替换、文本说明或功能删除都不能单独计为完成。

## 6. 暂不做的优化

在真实闭环稳定前，不优先投入多人协作、复杂工作流编排、Git 平台深度集成、模型多 Provider 自动竞价、Production 自动发布或原生 App。它们应建立在协议、状态机、安全边界和 Mobile Spec 行为已经稳定的基础上。
