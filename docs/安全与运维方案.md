# 安全与运维方案

## 1. 威胁模型

重点防范：

- 攻击者盗用手机 Session。
- Prompt、依赖安装脚本或生成代码尝试读取工作区外文件和云端凭证。
- 恶意任务执行挖矿、扫描、横向移动或高额资源消耗。
- 日志、diff、归档或模型上下文泄漏 Secret 和个人数据。
- 断线、重试或重复事件导致同一部署、外部写入或付费操作执行多次。
- 本机和云端同时修改项目，覆盖用户代码。

## 2. 身份和会话

### 当前 MVP

- 使用 PBKDF2-SHA256 加盐密码哈希。
- Session token 随机生成，数据库只保存 SHA-256 哈希。
- Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Lax`，有效期 7 天。
- 每次查询按 `owner_user_id` 限制项目访问。

### 公开测试前必须补齐

- 删除固定种子账号初始化路径，提供安全的管理员创建或邀请流程。
- 登录限速、失败次数退避和异常审计。
- 写接口 CSRF 防护或严格 Origin 校验。
- Session 列表、单个/全部撤销和密码修改后全量失效。
- 安全响应头、CSP、依赖漏洞扫描和自动 Secret 扫描。
- 若 Sites 外层保持私有访问，明确外层身份和应用内账号的双重访问关系。

## 3. 执行隔离

### Cloud Runner

- 每个 attempt 使用独立沙箱身份、文件系统和进程空间。
- 非 root、只挂载任务工作区、只读基础镜像、限制 CPU/内存/磁盘/进程数/时间。
- 网络默认拒绝，按依赖 registry、模型 Provider、部署 Provider 的域名和方法放行。
- 禁止 Docker socket、宿主设备、云实例元数据和其他租户存储。
- 依赖安装与项目命令分开记录，超时后杀死整个进程组。

### Desktop Agent（已移除，暂未纳入当前范围）

原计划的本机执行器隔离策略。该组件已从仓库移除，下列要求留作未来重新引入时的设计参考：

- 仅能访问用户批准的工作区和明确附加目录。
- 不接受来自手机浏览器的原始命令字符串。
- 所有动作需同时通过云端策略和本机策略；本机拒绝优先。
- 设备令牌可撤销，敏感凭证保存在操作系统安全存储。
- Agent 更新包必须签名并支持版本下限和紧急吊销。

## 4. 动作风险分级

| 级别 | 示例 | 默认策略 |
|---|---|---|
| Low | 读取工作区、写新文件、运行 lint/test | 已确认任务内自动允许 |
| Medium | 安装公开依赖、访问公开 API、创建 Preview | 首次展示范围，可按项目记忆 |
| High | 上传本机源码、使用第三方凭证、修改云数据库 | 每次明确确认 |
| Critical | Production 发布、支付、删除外部资源、破坏性数据迁移 | 强确认，不允许自动模式跳过 |

审批必须绑定 attempt、动作摘要、资源范围和到期时间，不能批准模糊的“以后所有操作”。

## 5. Secret 管理

- 平台只保存加密 Secret 或外部密钥管理服务引用。
- 执行器获得短期、最小权限、可审计的 `SecretGrant`。
- Secret 不进入 Prompt、事件 payload、命令行参数和源码归档。
- 日志进入存储和 UI 前执行格式、熵值和已知键名三类脱敏。
- 下载 ZIP 默认排除 `.env*`、密钥、证书、cookie、凭证目录和依赖缓存。
- Provider 授权撤销后，未开始的任务立即失效；运行中任务按策略取消。

## 6. 可靠性机制

- 任务创建、取消、审批和部署使用幂等键。
- 执行器使用带 fencing token 的租约；过期持有者不能继续提交结果。
- 事件先持久化再推送，客户端按游标恢复。
- 每个 Mobile Spec gate、构建前、部署前和成功后创建 checkpoint。
- 瞬时错误指数退避并限制次数；代码/验证错误由 Agent 在修复轮次内处理。
- 部署 Provider 超时后先按幂等键查询，不盲目再次创建部署。

## 7. 可观测性

### 指标

- 登录成功率和异常失败率。
- `plan_ready_latency`、排队时间、各 stage 时长和总交付时间。
- 首次构建成功率、Verify 失败率、部署成功率和重试率。
- 每个 Provider 的 token、成本、限流和错误分类。
- SSE 连接数、重连率、事件积压和端到端展示延迟。

### 日志和追踪

- `requestId`、`projectId`、`jobId`、`attemptId`、`actionId` 贯穿控制面和执行器。
- 用户可见日志与内部审计日志分层；前者脱敏并压缩噪声。
- 模型输入输出记录遵从可配置的数据保留策略，不存储隐藏推理内容。
- 关键外部写入保留 Provider 请求摘要、幂等键和结果证据。

### 告警

- 登录失败异常激增。
- 排队时间、事件延迟或失败率超过阈值。
- Secret 脱敏命中、策略拒绝或沙箱逃逸信号。
- 成本、token 或任务时长超过项目和账户预算。
- 部署已成功但平台交付记录未完成的状态不一致。

## 8. 备份与恢复

- 元数据数据库做定期备份并执行恢复演练。
- checkpoint manifest 和源码归档使用内容摘要校验。
- Artifact Store 开启版本或删除保护，清理任务使用可审计队列。
- 控制面完全重启后可从数据库恢复 queued/running 任务；租约过期的 attempt 标记 `expired`，不会在未知状态下自动继续外部写入。

## 9. 上线检查清单

- 固定测试密码、调试路由和演示数据已处理。
- 所有写 API 有鉴权、所有权检查、输入校验、限速和幂等。
- 依赖、许可证、Secret 和内网残留扫描通过。
- Cloud Runner 的目录、网络、资源和命令策略有自动测试。
- 取消、超时、断网、重复请求、Provider 限流和部署半成功均有演练。
- 用户能查看和撤销 Session、设备、第三方授权、项目和部署。
