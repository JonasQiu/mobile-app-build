# Mobile Build 文档中心

更新日期：2026-08-13

本目录同时描述当前已经上线的 MVP 和后续目标架构。阅读时以文档中的状态标记为准：

- **已实现**：代码存在并已通过当前项目验证。
- **演示实现**：界面和流程可操作，但背后尚未连接真实执行器。
- **待实现**：设计已经确定，尚无可用实现。
- **待决策**：需要产品、成本或合规选择后才能定稿。

## 推荐阅读顺序

1. [MVP 产品说明](MVP产品说明.md)：产品目标、用户流程、当前边界和验收口径。
2. [总体技术方案](总体技术方案.md)：系统分层、双执行模式、关键时序和技术选型。
3. [API 与事件协议](API与事件协议.md)：手机端、协调服务和执行器之间的稳定契约。
4. [数据模型](数据模型.md)：项目、任务、执行尝试、事件、快照、审批和部署数据。
5. [Mobile Spec 完整替换技术方案](Mobile-Spec完整替换技术方案.md)：Kernel、Skills、Adapter、迁移和等价验收。
6. [安全与运维](安全与运维方案.md)：权限、Secret、沙箱、审计、监控和故障恢复。
7. [开发、验证与部署手册](开发验证与部署手册.md)：本地运行、数据库迁移、发布、检查和回滚。
8. [实施路线图](实施路线图.md)：从交互 MVP 到真实构建闭环的里程碑和完成定义。

## 文档维护规则

- 改变接口、状态机或数据字段时，同时更新本目录与 [API 与事件协议](API与事件协议.md)。
- 改变用户流程或授权边界时，同时更新产品说明、安全方案和产品决策总表。
- 只有迁移矩阵全部通过行为测试，才能把 Mobile Spec 标记为“完整替换完成”。
- 文档不记录明文密码、API Key、部署令牌、设备令牌或真实用户数据。
