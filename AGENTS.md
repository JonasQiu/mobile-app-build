# SiteForge AI repository instructions

## Start here

Before changing code or documentation, read [the developer documentation index](docs/development/README.md). Then read the chapter that matches the task:

- Architecture or Runner boundaries: `docs/development/01-系统架构.md`
- Setup, environment, or local startup: `docs/development/02-本地开发.md`
- Stages, preview approval, checkpoints, pause, or rerun: `docs/development/03-执行工作流.md`
- API, status fields, authentication, or D1: `docs/development/04-API与数据.md`
- Tests or debugging: `docs/development/05-测试与排障.md`
- Sites publishing, Runner service, Tunnel, or rollback: `docs/development/06-部署与运维.md`

Use `docs/文档中心.md` for the longer product, architecture, protocol, security, and roadmap sources.

## Repository model

- `apps/web/` is the OpenAI Sites control plane. It owns identity, projects, preview approval, dispatch, trusted state synchronization, and artifact presentation.
- `packages/codegen/` is the Trusted Runner. It owns Mobile Spec execution, Codex/OpenAI calls, filesystem writes, dependency installation, builds, deployment, and health checks.
- `packages/mobile-spec/` owns specification schemas, templates, workflow state, and gates.
- `templates/next-web/` is the neutral generated-site template.
- The Web process must not execute Shell commands or access Runner credentials from the browser.

## Required behavior

- Preserve unrelated worktree changes. Inspect `git status` before editing.
- Preserve the existing package manager and lockfiles. Do not replace the project structure.
- Browser state must never create `delivered`, evidence, or a delivery URL.
- Do not start Codex, build, or deployment before the current preview option is approved by both the control plane and Runner.
- `continue` reuses valid successful checkpoints. Only `rerun` clears them.
- Progress, messages, events, and terminal states must come from trusted server or Runner data; do not simulate execution in the UI.
- Quick Tunnel is development/acceptance infrastructure, not persistent production hosting.
- Do not commit API keys, Bearer tokens, Sites bypass tokens, private paths, or generated user data.

## Change synchronization

- API or Runner status changes: update `docs/API与事件协议.md` and `docs/development/04-API与数据.md`.
- User workflow changes: update `docs/MVP产品说明.md` and `docs/development/03-执行工作流.md`.
- D1 changes: update `apps/web/db/schema.ts`, a migration in `apps/web/drizzle/`, runtime compatibility DDL in `apps/web/app/lib/server-auth.ts`, and data docs.
- Deployment, Secret, Runner, or Tunnel changes: update the security/operations docs and the matching development chapters.
- Narrative docs are maintained manually. `docs/实现状态快照.md` is generated by `scripts/sync-docs.mjs`.

## Validation

Run checks proportional to the changed surface before committing:

```bash
cd apps/web
npm run build
npm run lint
node --test tests/*.test.mjs
```

```bash
cd packages/codegen
npm test
```

```bash
cd packages/mobile-spec
npm test
```

For documentation changes, always run from the repository root:

```bash
node scripts/check-docs.mjs
git diff --check
```
