# Review

> **检查目标**：以 `proposal.md` 为为什么做、做什么、不做什么的产品边界，以 `specs/**/*.md` 为按页面组织的详细需求与行为契约，以 `design.md` 为实现方案，检查三者的完整性、一致性、内容边界和 Native 风险。
> 找出五类问题：**越界**、**矛盾**、**遗漏**、**不可追踪**、**模糊项**。
> **审查边界**：Review 只报告问题和证据，不重新设计方案、不补写需求、不拆任务。每个问题必须引用文件与位置，并指出应回改的 owning artifact。
> 仅当越界、矛盾、遗漏均为 0，Native 阻塞风险已关闭，且不存在未关闭的 High Severity 阻塞项时，文档最后一条状态行才可写为 pass。
