# 文本需求源

仅在生成或修订 artifact 且用户提供了直接文本或项目内需求文件时读取。

1. 原样读取用户目标、功能、内容、约束和明确验收，不用预设模板推断页面或功能。
2. 将文案中的例子视为需求事实，除非用户明确标记为参考或备选。
3. 文本足以明确为什么做、做什么、不做什么及关键行为时，可独立形成 Proposal 和 Specs，不要求补充望岳、Cooper 或其他链接。
4. 缺失事实会改变范围、核心交互、数据责任或验收时，记录为未决问题；不影响首版合理默认值的细节在 Design 中明确假设。
5. 同时存在链接、附件或截图时全部登记。文本与补充材料冲突且会影响范围或验收时，记录冲突、影响和待确认决策，不静默覆盖任一来源。
6. 不把文本映射到预设产品模板；页面、数据和交互必须从本次需求及其补充材料中派生。
