# 开发 Server 验证协议

仅当目标仓库存在明确开发 Server 启动命令，且验证计划判定本次适用时读取并交给 Verify subagent。

1. 使用仓库声明的启动命令，不猜测替代命令；记录命令、端口和启动时间。启动命令必须在沙箱外执行：首次运行即使用当前执行环境提供的提权或沙箱外执行能力，不得先在沙箱内试跑；无法申请、用户拒绝或授权失败时，记录 `environment` failure 并停止该启动验证，不得退回沙箱内运行。
2. 按仓库定义的 ready 日志、可访问 URL 或 health check 判断就绪，并保留成功证据或错误日志。
3. 验证结束后只清理由本次 Verify 启动的进程，不终止已有进程。
4. 启动失败必须分类：本次实现或配置缺陷为 `implementation`；依赖、凭证、网络、端口或运行环境问题为 `environment`；需求或方案变化为 `requirements`。不得为了启动成功而修改产品代码或配置。
